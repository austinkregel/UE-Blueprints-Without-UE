# Copilot Instructions for UE-Blueprints-Without-UE

## Project Overview
This is a desktop application that creates a visual node-based programming interface similar to Unreal Engine Blueprints. The goal is to provide a graphical way to edit code by parsing source files and building an interactive node graph interface. We are not building anything to do with games, 3d spaces, or similar. This is going to be a visual code editor.

### Core Concept
- Transform traditional code into visual nodes that can be connected to create program flow
- Initial focus on Laravel/PHP projects but designed to support any language with AST support
- Uses custom language servers for different programming languages
- Generates actual executable code from the visual node graph

## Technology Stack

### Frontend
- **Vue 3** (Composition API) - Main UI framework
- **Vite** - Build tool and dev server
- **TailwindCSS 4.x** - Styling framework with custom glass effects
- **Tauri 2.x** - Cross-platform desktop app framework

### Backend/Runtime
- **Rust** - Tauri backend for system operations
- **Custom Language Servers** - For parsing and code generation (currently PHP-focused)

### Testing
- **Vitest** - Unit testing framework
- **@vue/test-utils** - Vue component testing utilities

## Project Structure

### Core Components
- `src/App.vue` - Main application with node editor canvas
- `src/components/Nodes/` - Node implementations:
  - `NodeBase.vue` - Base node component with I/O connections
  - `FunctionNode.vue` - Function/method nodes
  - `SystemNode.vue` - System operation nodes
  - `VariableNode.vue` - Variable getter/setter nodes
- `src/components/NodeParts/` - I/O connection components
- `src/components/icons/` - Custom icons for execution and connections

### Utility Modules
- `src/utils/` - Core logic organized by domain:
  - `connection-manager.js` - Manages node connections and validation
  - `connection-utils.js` - Connection creation, type checking, auto-casting
  - `editor-utils.js` - Canvas operations and node positioning
  - `language-definition.js` - **Core language system** - Defines all node types, operations, and type system
  - `node-factory.js` - Factory functions for creating nodes from language definitions
  - `node-colors.js` - Node type to color mapping and theme system
  - `*-node-utils.js` - Node type-specific utilities
  - `io-utils.js` - Input/output handling
  - `id-utils.js` - Unique ID generation for nodes

## Key Features & Concepts

### Language Definition System
1. **Comprehensive Type System**: All supported data types (int, float, string, bool, array, object, etc.) with compatibility rules
2. **Node Categories**: Organized node types (FUNCTION, VARIABLE, CONTROL, MATH, STRING, ARRAY, COMPARISON, CAST, SYSTEM)
3. **Node Definitions**: Complete specifications for all available nodes including inputs, outputs, and behavior
4. **Color Coordination**: Automatic color assignment based on node categories and types
5. **Node Factory**: Programmatic node creation from language definitions

### Node System
1. **Node Types**:
   - Function nodes (user-defined and built-in functions)
   - Control flow nodes (if, for, while, foreach, switch)
   - **Execution flow nodes (sequence, branch, gate, multigate, do_once, delay, flip_flop, etc.)**
   - Math operation nodes (add, subtract, multiply, etc.)
   - String manipulation nodes (concat, length, substring, etc.)
   - Array operation nodes (push, pop, get, set, etc.)
   - Comparison nodes (equals, greater than, logical operations)
   - Type casting nodes (to_int, to_string, etc.)
   - Variable nodes (getters/setters)
   - System nodes (print, var_dump, exit)

2. **I/O System**:
   - **Automatic execution pins**: Execution flow pins are automatically shown based on node definitions, not manually added
   - **Exec pins**: White execution flow pins for controlling when and how nodes execute
   - Data pins (typed data flow)
   - Auto-casting between compatible types
   - Type validation and connection rules
   - Visual connection status indicators

3. **Execution Flow Control**:
   - **Sequence**: Execute multiple outputs in order
   - **Branch**: Conditional execution (same as If but clearer exec flow)
   - **Gate**: Control execution flow with open/close state
   - **MultiGate**: Route execution to different outputs in sequence or randomly
   - **DoOnce**: Execute only once until reset
   - **DoN**: Execute N times then stop
   - **Delay**: Delay execution for specified duration
   - **FlipFlop**: Alternate between two outputs
   - **For/While/ForEach Loops**: Advanced loop control with proper exec flow

4. **Connection Management**:
   - Visual connection rendering with SVG paths
   - Drag-and-drop connection creation
   - Duplicate connection prevention
   - Self-connection prevention
   - Connection status indicators (orange ConnectionIcons when connected)

### Visual Features
- Grid background for precise positioning
- Glass morphism styling for nodes
- **Comprehensive color system**: Each node category has its own color (blue=function, purple=variable, green=math, yellow=control, red=comparison, etc.)
- **Node Palette**: Searchable, categorized list of all available nodes
- Debug mode with visual indicators
- Responsive connection paths
- Mouse-based interaction system
- Drag-and-drop node creation from palette

## Development Guidelines

### Code Organization
- Use Vue 3 Composition API with `<script setup>`
- Organize utilities by domain/responsibility
- Keep components focused and reusable
- **Node definitions drive behavior**: Execution pins, I/O, and colors are automatically determined from language definitions
- Use TypeScript-style JSDoc comments
- Files should be no more than 500 lines of code
- Files should be organized so it is easiest for Copilot to understand. Human readability is not a concern.
- When a file reaches 500 lines of code it's a sign we need to refactor it and break it into smaller chunks for Copilot to prevent code corruption.

### Styling Conventions
- Use TailwindCSS utility classes
- Custom CSS for node glass effects and grid backgrounds
- **Language-driven color system**: Colors automatically assigned based on language definition categories
- **Comprehensive type colors**: Each data type has its own color for visual consistency
- Responsive design principles
- Dark theme with themed accent colors per node category
- Node palette with category-based organization

### Testing Strategy
- Unit tests for utility functions
- Component tests for Vue components
- Integration tests for node connection logic
- Coverage tracking with Istanbul

### State Management
- Reactive refs for node and connection state
- Computed properties for derived state
- Event-driven architecture for user interactions
- Local state management (no external store needed currently)

## Architecture Decisions
- **Modular Utilities**: Each utility module has a specific responsibility
- **Component Composition**: Reusable components with clear interfaces
- **Event-Driven Connections**: Mouse events drive connection creation
- **SVG for Graphics**: All connections and visual elements use SVG
- **Desktop-First**: Optimized for desktop interaction patterns

## Future Considerations
